### 1.3 AI 内容生产架构（内部会话还原，核心）

历史 Agent 还原出的标准链路：

```text
原始资讯 newsList（可嵌套 stockList / sectorList）
        │
   Code 节点：JSON 清洗 / 拆分（容错双重转义、裸换行）
        ├─ stockList  → 关注个股三段流（P1/P2）
        ├─ sectorList → 关注板块三段流（P3/P4）
        └─ clean newsList
        │
   各 LLM 节点（仅 System Prompt + JSON 输出）
        │
   汇总字段：gzgg / gzbk / jrzysj / scywhg / dpzj / gyhqyw …
        │
   早晚报 / 早点听 / 诊股问句 等客户端模块消费
```

**三段式可复用模板（个股 / 板块通用）：**

1. **分类总结**：按优先级标签抽取事件摘要（20–35 字级）  
2. **去重合并**：同标的同事件合并，保留来源 `newsId`  
3. **综合分析**：机构研报式短文，禁止买卖建议与绝对化表述  

**编排引擎：** Dify（Start / Code / IF / Iteration / LLM / End）  
**原则：** 规则算异动，LLM 写文案；先批处理再个性化拼贴。

## 3. 关键数据流与交互流

### 3.1 资讯 → 早晚报

```text
外部资讯源（财联社 / 九方智讯 / 公告 / 研报…）
  → 入库并关联股票/板块
  → Dify：拆分 + 分类总结 + 去重 + 综合分析
  → 生成全量内容字段包
  → 用户打开早晚报时按自选股/关注板块拼贴展示
```

### 3.2 个股页 → 诊股

```text
进入个股详情
  →（可选）展示 AI 要闻横幅 / 未读气泡 / 诊股红点
  → 用户点击诊股
  → 进入诊股对话页（可自动带问句或一点发送）
  → LLM 结合行情/资金/消息等多维上下文生成解读
```

**已知限制（内部确认）：** 诊股对话**不支持后台继续生成**——退出对话页即中断；因此运营文案不能写成「已分析完成」。

### 3.3 异动特别提醒

```text
单票行情字段（涨跌幅、振幅、量比、成交额比、涨跌停、moveList…）
  → Code 准入（布尔判定）
  → 命中则 LLM 生成「异动总结 + 原因 + 条件式预测」
  → 写入晚报特别提醒栏目
```

## 4. 优点

### 4.1 产品层

1. **闭环完整**：行情浏览、AI 解读、资讯早晚报、筹码决策工具形成「看—懂—跟」路径，降低散户信息整合成本。  
2. **个性化成本可控**：全量预生成 + 自选拼贴，比「每用户实时全链路 LLM」更易扩容、更稳。  
3. **运营抓手丰富**：红点、气泡、横幅、分时段文案、未读要闻带问句，能把诊股从「被动入口」做成「场景转化」。  
4. **合规意识前置**：提示词层明确禁止荐股与编造数据，降低投顾合规风险。  
5. **筹码差异化**：公开侧有筹码峰教育内容 + 筹码大师「弹/突」信号与信号池，形成可感知的决策卖点。

### 4.2 技术 / 工程层

1. **Dify 工作流可编排**：总结 / 去重 / 分析解耦，个股与板块可复用三段式模板。  
2. **规则 + LLM 分工清晰**：异动用阈值门槛，文案用模型，减少幻觉驱动的「假异动」。  
3. **结构化 JSON 契约**：便于下游拼装、测试用例（如 P1/P2 TC001–TC018）与质量抽检。  
4. **垂类模型与知识库**：九章大模型 + 图谱/因子，比通用 Chatbot 更贴合证券场景。  
5. **多端触达**：小程序获客轻、APP 承载重图表与付费工具，形成漏斗。

## 5. 缺点与风险

### 5.1 产品体验

1. **诊股生成非持久化**：退出对话即中断，无法做「后台生成完成再提醒」，强引导与真实能力存在预期落差。  
2. **小程序与 APP 能力割裂**：重筹码图表、Level2、付费信号多在 APP；小程序若仅做诊股/资讯，用户会感知「功能不全」。  
3. **ETF / 关联产品空态**：板块无对应 ETF 时易出现大片空白；热门 ETF 乱推又损害相关性信任（已有产品方案，落地情况待验证）。  
4. **诊股转化仍偏低**：点击率约 5.8%、人均互动弱，说明「解读价值」尚未形成强习惯。  
5. **同质化竞争激烈**：问财、妙想、各券商 AI 选股/诊股并存，纯话术优势难持久。

### 5.2 技术与内容质量

1. **入参脆弱**：`newsList` 常为双重转义 JSON / HTML 正文 / 裸换行，Code 节点易 JSONDecodeError。  
2. **提示词膨胀**：规则极细、整段重发迭代，维护成本高，模型仍可能漏关键数字、错 type、弱关联误出。  
3. **去重无向量时漏杀/误杀**：同 Label 近 20 条文本相似判断，稳定性一般。  
4. **字段契约漂移**：蛇形/驼峰、涨跌停编码、量比时点等多变，Code 与 LLM 变量易不同步。  
5. **幻觉与归因风险**：即使有禁止编造规则，异动「原因分析」在缺事件映射时仍可能空泛或误归因。

### 5.3 商业与合规

1. **付费工具依赖信任**：筹码大师等信号若胜率体感不稳，易引发投诉与退费压力。  
2. **投顾资质边界**：AI 文案需持续守住「不构成投资建议」；运营话术若过猛，合规风险上升。  
3. **数据源稳定性**：资讯/行情上游限流或口径变更，会直接影响早晚报与诊股质量。  
4. **品牌命名外部不可检索**：「筹码科学」若作为对外名，目前公开认知几乎为零，获客与口碑沉淀不利（若仅为内部代号则无此问题）。

## 6. 架构优缺点对照表

| 维度 | 优势 | 劣势 |
|------|------|------|
| 内容生产 | 批处理 + 拼贴，吞吐好 | 实时性/个性化深度受限 |
| AI 编排 | Dify 可视化、模块复用 | 提示词与节点配置易腐化 |
| 诊股体验 | 场景入口多、可带问句 | 会话中断、后台生成缺失 |
| 筹码能力 | 有信号产品与形态教育 | 小程序侧图表能力偏弱 |
| 合规 | 提示词硬约束齐全 | 运营文案与模型输出需持续审计 |
| 多端 | 小程序拉新 + APP 变现 | 能力不一致导致体验断裂 |

## 7. 改进建议（调研导向）

1. **诊股会话任务化**：生成任务落库 + 后台续跑 + 「分析完成」推送，对齐运营预期。  
2. **统一标的与字段契约**：`symbol/market`、资讯 JSON Schema、模块字段字典版本化。  
3. **去重升级**：Label 粗筛 + Embedding 精排，降低误合并。  
4. **小程序补齐轻量筹码视图**：即使不做完整筹码大师，也应提供成本分布摘要/信号状态，缩短与 APP 的能力鸿沟。  
5. **空态策略产品化**：相关 ETF 无数据时隐藏或降级成分股，禁止无关联热门兜底。  
6. **对外命名澄清**：若「筹码科学」为正式品牌，需补齐小程序名、简介、搜索关键词与官网入口；若为内部代号，文档中应与「九方诊股 / AI 灵犀 / 筹码大师」做映射表，避免调研与协作歧义。
