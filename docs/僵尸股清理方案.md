# 僵尸股清理方案

> 版本：v1.0（草案）
> 适用对象：自营/资管投资组合、股票池与名单管理、风控与合规
> 说明：本文中的所有阈值均为**建议起点**，需结合自身资金规模、产品类型、持仓集中度与所在市场（沪深主板 / 科创创业板 / 北交所 / 新三板 / 港美股）做校准后再固化。

---

## 一、背景与目标

长期持有或长期挂在股票池里的"僵尸股"，会带来四类实际损失：

1. **资金占用**：仓位被无收益、无流动性的标的锁死，挤占了有效策略的额度。
2. **估值与净值失真**：无成交或极稀疏成交的标的，收盘价不代表可变现价格，产品净值虚高，一旦赎回集中到来会形成对存量持有人的不公平。
3. **尾部风险**：僵尸股与退市、立案调查、非标审计意见、资金占用/违规担保高度相关，一次爆雷可以吃掉一年的超额。
4. **运营成本**：每只标的都要消耗研究覆盖、估值复核、信息披露、公司行动处理的固定人力。

本方案要解决的是端到端的一整条链路，而不只是"卖掉几只票"：

- **建立统一口径**：什么算僵尸股，用可复算的量化规则定义，消除各团队各说各话。
- **建立自动识别**：从行情、财务、公告三类数据自动出名单，定期跑批，而不是靠人工回忆。
- **建立分级处置**：不同严重程度对应不同处置手段和时限，避免一刀切砸盘。
- **建立防复发**：入池前置校验 + 持仓期持续监控，堵住新的僵尸股进来。

**总体目标**：完成一轮存量清理后，僵尸股市值占组合总市值的比例降至设定上限以内（建议 ≤ 1%），并将清理过程的实现冲击成本控制在预算以内。

---

## 二、"僵尸股"的定义口径

僵尸股 = **丧失流动性** + **丧失基本面造血能力** + **可能存在治理/合规瑕疵** 的标的。三个维度中，流动性是必要条件，另外两个是加重条件。

### 2.1 维度一：流动性枯竭（必要条件）

在**过去 250 个交易日**的观察窗口内，满足以下任意两项即认定流动性枯竭：

| 编号 | 指标 | 建议阈值（A 股主板） | 建议阈值（新三板/北交所） |
|---|---|---|---|
| L1 | 日均成交额 | < 500 万元 | < 5 万元 |
| L2 | 有成交交易日占比 | < 60% | < 20% |
| L3 | 最长连续零成交天数 | ≥ 10 个交易日 | ≥ 30 个交易日 |
| L4 | 年化换手率 | < 30% | < 5% |
| L5 | 自由流通市值 | < 10 亿元 | < 1 亿元 |
| L6 | 本方持仓 / 日均成交额（清仓天数） | > 20 个交易日 | > 60 个交易日 |
| L7 | 停牌天数 | 连续停牌 ≥ 60 个自然日 | 连续停牌 ≥ 60 个自然日 |

其中 **L6 清仓天数**是最贴近实际痛感的指标：它直接回答"按不冲击市场的节奏，我要卖多久才能出来"。建议把它作为核心指标，权重最高。

### 2.2 维度二：基本面枯竭

| 编号 | 指标 | 建议阈值 |
|---|---|---|
| F1 | 扣非归母净利润 | 连续 2 个完整会计年度为负 |
| F2 | 营业收入 | 连续 2 年 < 3 亿元，或同比降幅连续 2 年 > 30% |
| F3 | 经营性现金流净额 | 连续 3 年为负 |
| F4 | 归属母公司净资产 | 为负，或资产负债率 > 90% |
| F5 | 研发/资本开支 | 连续 2 年接近于零（业务实质停摆的信号） |
| F6 | 员工人数 | 同比降幅 > 50%，或绝对人数低于行业最低运营门槛 |

### 2.3 维度三：治理与合规瑕疵

| 编号 | 指标 |
|---|---|
| G1 | 最近一期审计报告为非标意见（保留 / 无法表示 / 否定） |
| G2 | 被实施退市风险警示（\*ST）或其他风险警示（ST） |
| G3 | 公司或董监高被立案调查、被采取行政监管措施 |
| G4 | 年报/半年报未按期披露 |
| G5 | 存在控股股东资金占用、违规担保未解决 |
| G6 | 控股股东所持股份被高比例质押（> 80%）或司法冻结 |
| G7 | 主要银行账户被冻结、被申请重整/破产清算 |

### 2.4 综合评分与分级

采用百分制加权打分，便于排序与分级处置：

```
僵尸分 = 流动性得分 × 0.45 + 基本面得分 × 0.30 + 治理得分 × 0.25
```

各维度得分 = （该维度命中指标数 / 该维度指标总数）× 100。

在此基础上设置**红线直达规则**：命中 G1、G2、G3、G7 中任意一项，或命中 L7，僵尸分直接置为 90 分起。

| 等级 | 僵尸分 | 定性 | 处置方向 |
|---|---|---|---|
| **L0 正常** | < 50 | 无异常 | 常规管理 |
| **L1 观察** | 50 ~ 69 | 流动性边际恶化 | 进观察名单，禁止加仓，月度复核 |
| **L2 清理** | 70 ~ 84 | 已构成僵尸股 | 限期减持至零，走常规二级市场路径 |
| **L3 立即处置** | ≥ 85 或触发红线 | 高危 | 立即禁投冻结，启动特殊处置通道 |

## 三、识别流程与技术实现

### 3.1 数据准备

| 数据域 | 内容 | 频率 | 来源 |
|---|---|---|---|
| 行情 | 日线开高低收、成交量、成交额、停复牌标志、流通股本 | 日 | 行情商 / 交易所 |
| 财务 | 定期报告主要科目、审计意见 | 季 | 财务数据库 |
| 公告与事件 | ST 标记、立案、质押冻结、重整、退市流程节点 | 日 | 公告数据 / 舆情 |
| 持仓 | 各产品/账户逐标的持仓数量与成本 | 日 | 估值/核算系统 |

数据质量是这套方案的地基，落地前必须先做三项校验：**停牌日不能被当成零成交日误判**、**复权口径统一**、**退市与代码变更的历史映射完整**。这三点任意一项出错，名单就会大面积误判。

### 3.2 流动性指标计算（SQL 示例）

以下按标准日线表 `daily_quote(trade_date, sec_code, amount, volume, close, free_float_shares, is_suspended)` 编写，可直接改造：

```sql
WITH win AS (
    SELECT sec_code,
           trade_date,
           amount,
           volume,
           close,
           free_float_shares,
           is_suspended,
           ROW_NUMBER() OVER (PARTITION BY sec_code ORDER BY trade_date DESC) AS rn
    FROM daily_quote
    WHERE trade_date <= :as_of_date
),
w250 AS (
    SELECT * FROM win WHERE rn <= 250
),
agg AS (
    SELECT
        sec_code,
        -- L1 日均成交额（剔除停牌日，避免把停牌算成"低迷"）
        AVG(CASE WHEN is_suspended = 0 THEN amount END)                     AS avg_amount,
        -- L2 有成交交易日占比
        SUM(CASE WHEN is_suspended = 0 AND volume > 0 THEN 1 ELSE 0 END)
            * 1.0
            / NULLIF(SUM(CASE WHEN is_suspended = 0 THEN 1 ELSE 0 END), 0)  AS active_day_ratio,
        -- L4 年化换手率
        SUM(CASE WHEN is_suspended = 0 THEN volume ELSE 0 END)
            / NULLIF(MAX(free_float_shares), 0)                             AS turnover_1y,
        -- L5 自由流通市值（取最新一日）
        MAX(CASE WHEN rn = 1 THEN close * free_float_shares END)            AS free_float_mv,
        -- L7 近期停牌天数
        SUM(CASE WHEN is_suspended = 1 AND rn <= 60 THEN 1 ELSE 0 END)      AS suspended_60d
    FROM w250
    GROUP BY sec_code
)
SELECT
    a.sec_code,
    a.avg_amount,
    a.active_day_ratio,
    a.turnover_1y,
    a.free_float_mv,
    a.suspended_60d,
    -- L6 清仓天数：按不超过日均成交额 20% 的节奏估算
    p.market_value / NULLIF(a.avg_amount * 0.20, 0)                         AS days_to_liquidate
FROM agg a
LEFT JOIN position_snapshot p
       ON p.sec_code = a.sec_code
      AND p.as_of_date = :as_of_date;
```

**注意**：连续零成交天数（L3）用窗口函数做 gap-and-islands 更稳妥，为保持示例简洁此处省略，落地时单独实现。

### 3.3 打分与出名单（Python 骨架）

```python
from dataclasses import dataclass

LIQ_RULES = {
    "L1": lambda r: r.avg_amount < 5_000_000,
    "L2": lambda r: r.active_day_ratio < 0.60,
    "L3": lambda r: r.max_zero_volume_streak >= 10,
    "L4": lambda r: r.turnover_1y < 0.30,
    "L5": lambda r: r.free_float_mv < 1_000_000_000,
    "L6": lambda r: r.days_to_liquidate > 20,
    "L7": lambda r: r.suspended_60d >= 60,
}
FUND_RULES = {...}   # F1~F6，同样的写法
GOV_RULES  = {...}   # G1~G7

RED_LINES = {"G1", "G2", "G3", "G7", "L7"}
WEIGHTS = {"liq": 0.45, "fund": 0.30, "gov": 0.25}


@dataclass
class ZombieResult:
    sec_code: str
    score: float
    level: str
    hits: list[str]       # 命中的规则编号，用于向投委会解释与申诉复核


def score_one(row) -> ZombieResult:
    hits = [k for rules in (LIQ_RULES, FUND_RULES, GOV_RULES)
            for k, fn in rules.items() if fn(row)]

    # 流动性是必要条件：流动性维度命中不足 2 项，直接判正常
    liq_hits = [h for h in hits if h.startswith("L")]
    if len(liq_hits) < 2:
        return ZombieResult(row.sec_code, 0.0, "L0", hits)

    def pct(rules):
        return len([h for h in hits if h in rules]) / len(rules) * 100

    score = (pct(LIQ_RULES) * WEIGHTS["liq"]
             + pct(FUND_RULES) * WEIGHTS["fund"]
             + pct(GOV_RULES) * WEIGHTS["gov"])

    if RED_LINES & set(hits):
        score = max(score, 90.0)

    level = ("L3" if score >= 85 else
             "L2" if score >= 70 else
             "L1" if score >= 50 else "L0")
    return ZombieResult(row.sec_code, round(score, 2), level, hits)
```

打分结果必须**落库留痕**（标的、评分日、得分、命中规则、所用数据版本），这既是后续申诉复核的依据，也是应对监管与内部审计问询的证据链。

### 3.4 跑批节奏

- **日频**：红线事件扫描（G1~G7）、停牌监控。命中即触发即时预警，不等月度。
- **周频**：流动性指标全量重算，更新观察名单。
- **月频**：完整三维打分，出正式《僵尸股名单》提交投决/风控例会。
- **季频**：定期报告披露后重算基本面维度，并做一次阈值有效性回顾。

## 四、分级处置策略

### 4.1 L1 观察级

- 加入观察名单，**禁止新增买入**（含所有产品、所有策略）。
- 要求研究员出具一页纸的持有理由说明，明确"继续持有的触发条件与放弃条件"。
- 月度复核，连续 2 个月停留在 L1 且分数上行的，自动升级为 L2。

### 4.2 L2 清理级

- **限期减持至零**，建议时限为 60 个交易日内完成，可按标的实际流动性申请一次展期。
- **交易纪律**（防止自己把自己砸在里面）：
  - 单日成交量不超过该标的当日市场成交量的 **20%**；流动性极差的（L6 > 60 天）压到 10%。
  - 采用 VWAP/TWAP 分批算法单，**禁止市价单一次性挂出**。
  - 避免开盘集合竞价与收盘前 10 分钟操作，规避收盘价影响的合规质疑。
  - 单日跌幅超过阈值（如 -7%）时暂停当日剩余卖出，次日重评。
- **进度看板**：按标的跟踪剩余仓位、已实现冲击成本（vs. 决策时点 arrival price）、预计完成日。
- 减持涉及大股东/董监高身份、或持股比例触及举牌线的，先走**信息披露与减持规则**校验（集中竞价与大宗交易的比例与预披露要求），由合规出具意见后方可下单。

### 4.3 L3 立即处置级

- **立即冻结**：全产品线禁投、禁加仓，交易系统硬拦截。
- **穷举退出通道**，按优先级：
  1. 二级市场分批卖出（若仍有成交）；
  2. 大宗交易/协议转让寻找对手方；
  3. 参与公司回购、要约收购、重整方案中的现金选择权；
  4. 确无通道的，转入**流动性受限资产**管理。
- **估值处理**：对长期停牌、无活跃市场的标的，停止使用最后收盘价，改用第三方估值或按内部估值政策计提流动性折价，并履行估值委员会审议与信息披露程序。这一步是保护存量持有人的关键，不能省。
- 涉及退市整理期的，明确是否参与整理期交易，并对退市后进入两网及退市公司股份转让系统的处置路径预先做出安排。

### 4.4 特殊情形豁免

以下情形允许申请豁免，但必须书面申报、限时有效（建议单次不超过一个季度）并由风控与投决双签：

- 处于**重整/重组关键节点**，退出反而毁灭价值；
- 因**司法冻结、限售期、股份支付锁定**等客观原因不可交易；
- 属于**战略配售/定增**尚在锁定期内；
- 被动跟踪指数产品中的成份股（受合同复制约束）。

豁免不等于免除监控，豁免期内仍按 L3 频率报送。

## 五、组织分工与流程

| 环节 | 主责 | 配合 | 产出 |
|---|---|---|---|
| 口径与阈值制定 | 风控部 | 投研、合规 | 《僵尸股认定标准》 |
| 数据接入与跑批 | IT / 数据团队 | 风控 | 名单表、预警推送 |
| 名单复核与申诉 | 投研部 | 风控 | 复核意见、豁免申请 |
| 处置决策 | 投资决策委员会 | 风控、合规 | 处置指令与时限 |
| 交易执行 | 交易室 | 投资经理 | 执行报告、冲击成本归因 |
| 合规校验 | 合规部 | — | 减持/披露合规意见 |
| 估值调整 | 估值小组 / 运营 | 托管行、会计师 | 估值备忘、披露文件 |
| 效果验收与复盘 | 风控部 | 全部 | 季度复盘报告 |

**申诉机制**：投研对名单有异议的，可在名单下发后的固定窗口内提交申诉，需附可验证的新信息（如已披露的重组进展、成交回暖数据）。风控在窗口内给出结论；逾期未申诉视为认可。误杀率是这套体系的重要健康指标，必须统计。

## 六、实施阶段

不按日历排期，按**里程碑 + 准出条件**推进，每个阶段完成准出条件后才进入下一阶段：

**阶段一 · 口径与数据就绪**
- 产出：认定标准文档定稿；行情/财务/公告/持仓四类数据接入完成并通过质量校验。
- 准出：用历史数据回溯近 3 年，人工抽样 50 只标的验证判定结果，准确率 ≥ 90%，且无停牌误判。

**阶段二 · 存量摸底**
- 产出：全组合僵尸股清单，含只数、市值、占比、分级分布、预估清仓天数与预估冲击成本。
- 准出：清单经投委会确认，处置优先级排序完成。

**阶段三 · 存量清理**
- 产出：按 L3 → L2 顺序执行处置；每周更新进度看板。
- 准出：L3 全部处置或转入受限资产管理；L2 完成率 ≥ 95%；实现冲击成本不超预算。

**阶段四 · 机制固化与防复发**
- 产出：入池前置校验上线（新标的入池即跑一次僵尸分，L1 以上不得入池）；日/周/月跑批自动化；预警推送接入日常工作流。
- 准出：连续两个跑批周期名单稳定、无人工干预；防复发规则在交易系统中硬约束生效。

**阶段五 · 常态化运营**
- 季度复盘阈值有效性，根据市场环境调整参数（例如熊市整体缩量时，绝对成交额阈值需相应下调，否则会大规模误判）。

## 七、风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| 砸盘风险 | 集中减持导致价格螺旋下跌，卖出成本远超预期 | 严格执行成交量占比上限、分批算法单、设置单日熔断 |
| 误杀风险 | 把处于底部反转或重组前夜的标的当僵尸股清掉 | 双维度确认 + 申诉机制 + 统计误杀率并反向调参 |
| 合规风险 | 减持比例、预披露、敏感期交易违规 | 下单前合规硬校验，敏感期名单系统拦截 |
| 内幕信息风险 | 因参与重整谈判等触及内幕信息，导致不得交易 | 建立信息隔离墙，涉密标的进入禁止交易名单 |
| 估值风险 | 长期停牌股仍按停牌前价格估值，净值失真 | 触发条件明确的强制估值调整流程，估值委员会审议 |
| 顺周期风险 | 全市场缩量期阈值不变 → 名单暴增 | 阈值改为相对分位数（如全市场成交额后 5% 分位）而非绝对值 |
| 税务与结算 | 集中处置带来的税负与交割安排 | 处置前做税务测算，跨年度平滑 |

**关于顺周期风险的补充**：这是实操中最容易翻车的一点。建议流动性指标同时保留"绝对阈值"和"全市场分位数阈值"两套口径，取**两者同时命中**才算数，可以显著降低系统性缩量期的误判。

## 八、效果度量

| 指标 | 定义 | 目标 |
|---|---|---|
| 僵尸股市值占比 | 僵尸股市值 / 组合总市值 | ≤ 1% |
| 僵尸股只数占比 | 僵尸股只数 / 持仓只数 | ≤ 3% |
| 清理完成率 | 已清零标的数 / 应清理标的数 | ≥ 95% |
| 实现冲击成本 | 成交均价 vs. 决策时点价格（bps） | ≤ 预算值 |
| 平均清仓天数 | 从下达指令到清零的交易日均值 | 逐季下降 |
| 误杀率 | 申诉成立数 / 名单总数 | ≤ 5% |
| 复发率 | 清理后 12 个月内重新买入并再次入选的标的数 | 0 |
| 名单时效 | 红线事件发生到预警送达的时延 | ≤ 1 个交易日 |

## 附录 A：如果口径是"僵尸股票账户"（睡眠户/久悬户）

若本方案实际针对的是**长期不动的客户股票账户**清理，核心逻辑与上文一致（识别 → 分级 → 处置 → 防复发），但要点不同，简述如下：

**认定条件**（需同时满足，具体以适用的账户管理规则为准）：
- 连续 3 年以上无交易记录、无查询、无变更等主动指令；
- 账户内证券余额为零；
- 资金余额低于设定的小额门槛；
- 无未了结的权益、质押、司法冻结或纠纷。

**处置流程**：
1. **筛查出名单**，逐户核验资金与证券余额、权益归属；
2. **多渠道告知**（短信、电话、邮寄、网站公告），保留完整告知留痕，设置合理的异议期；
3. **异议期届满后**执行休眠/注销，资金按规定转入指定账户单独管理；
4. **保留恢复通道**：客户本人持有效身份证明可随时申请恢复，且不得设置不合理障碍；
5. **档案留存**：告知记录、操作日志、双人复核签字，保存期限满足监管要求。

**红线**：不得擅自处置客户资产；不得因清理导致客户权益（分红、配股、转增）灭失；不得在有司法冻结或争议未决时操作；全流程必须双人复核并可追溯。
